# 한글 문서(.hwp / .hwpx) 읽기·쓰기

## 왜 이 스킬이 필요한가

- **.hwp**는 텍스트 파일이 아니다. OLE 복합 문서 안에 zlib으로 압축된 레코드가 들어 있고, 본문은 UTF-16에 표·각주 같은 제어문자가 섞여 있다. 그래서 그냥 열거나 `cp949`/`utf-8`로 디코딩하면 글자가 깨지고, 바이트를 직접 써서 만든 파일은 한글이 열지 못한다.
- **.hwpx**는 ZIP 안의 XML이지만, `mimetype`이 맨 앞에 무압축으로 있어야 하고 줄 배치 캐시(`linesegarray`)가 있어서 손으로 고치면 글자가 겹치거나 파일이 열리지 않는다.

`scripts/hwp.py`가 이 문제를 모두 처리한다. 파이썬 3.8+ 표준 라이브러리만 쓰므로 설치할 것이 없다. **한글 문서를 직접 파싱하거나 바이트를 직접 쓰는 코드를 새로 짜지 말고 반드시 이 도구를 쓴다.**

도구 경로는 이 SKILL.md가 있는 폴더 기준 `scripts/hwp.py`다(아래에서는 `HWP`로 줄여 쓴다). 실행 예: `python3 /path/to/hangul-hwp/scripts/hwp.py read 문서.hwp`

## 작업별 방법

### 1. 읽기 — "이 한글 파일 요약해줘", "내용 뭐야"

```bash
python3 HWP read 문서.hwp                 # 마크다운 (기본). 표는 표로, 병합 셀은 HTML 표로
python3 HWP read 문서.hwpx --format text  # 순수 텍스트
python3 HWP read 문서.hwp --format json   # 구조(문단/표/셀 주소)까지
python3 HWP info 문서.hwp                 # 형식·버전·보호 여부·문단/표 개수
```

- 긴 문서는 `-o 내용.md`로 저장한 뒤 필요한 부분만 읽는다.
- 출력의 `[그림]`, `[수식: ...]`, `[^1]`(각주 위치)은 도구가 넣은 표시다. 원문 글자가 아니다.
- `> 머리말:` / `> 꼬리말:` 줄은 쪽 머리·꼬리에 있던 글이다.
- 개요·문단 번호(1., 가., ①처럼 한글이 자동으로 붙이는 번호)는 문서에 글자로 저장되지 않아서 읽기 결과에 나오지 않는다. 사용자가 번호를 물으면 이 점을 알려 준다.

### 2. 양식 채우기 — "이 서식에 내 정보 넣어줘", "{{이름}} 자리에 홍길동"

원본 서식(글꼴·표·쪽 설정)을 그대로 두고 글자만 바꾸는 작업이다. **원본을 새로 만들어 버리지 말 것.**

1. 먼저 읽어서 어디를 바꿀지 확인한다: `python3 HWP read 양식.hwp`
2. 표 안의 빈칸을 채울 때는 셀 주소를 본다:
   ```bash
   python3 HWP cells 양식.hwp
   # [표 0]
   #   (행 0, 열 0): 성명
   #   (행 0, 열 1): 〈빈 칸〉
   ```
   **표·행·열 번호는 모두 0부터 센다.** 문서의 첫 번째 표가 `[표 0]`이다. `--table`에는 `cells`가 보여 준 번호를 그대로 쓴다.
   라벨 바로 오른쪽 칸이 항상 입력 칸인 것은 아니다(좁은 여백용 빈 칸이 끼어 있는 양식이 많다). 열 번호와 병합 정보를 보고 실제 입력 칸을 고른다.
3. 채운다. 결과는 항상 **새 파일**로 저장된다(원본은 덮어쓰지 않는다).
   ```bash
   # 셀 채우기 (여러 개는 JSON: [{"table":0,"row":0,"col":1,"text":"홍길동"}, ...])
   python3 HWP set-cell 양식.hwp -o 완성.hwp --table 0 --row 0 --col 1 --text "홍길동"
   python3 HWP set-cell 양식.hwp -o 완성.hwp --map 셀.json

   # 글자 바꾸기 (자리표시자, 날짜, 이름 등)
   python3 HWP replace 양식.hwpx -o 완성.hwpx --pair "{{이름}}" "홍길동" --pair "0000년 00월 00일" "2026년 1월 5일"
   python3 HWP replace 양식.hwp -o 완성.hwp --map 값.json      # {"{{이름}}": "홍길동", ...}
   ```
   "어디가 아직 안 채워졌나"를 물으면 `〈빈 칸〉` 셀과 함께 `0000년 00월 00일`, `○○○`, `____`, `입력해 주세요`, `{{…}}` 같은 자리표시 글도 미입력으로 본다. 라벨 옆의 좁은 빈 열(여백용)은 빼고 센다.
4. 도구가 출력하는 결과를 확인한다:
   - `→ 0곳`이면 그 글자를 찾지 못한 것이다. 표시상 같아 보여도 띄어쓰기, 전각/반각, 글자 사이에 낀 필드(누름틀) 때문에 다를 수 있다. `read`로 실제 글자를 다시 보고 정확한 문자열로 재시도한다. 모두 찾아야만 저장하려면 `--strict`.
   - `보존: 본문 외 ... 원본과 바이트 단위로 동일`은 고친 곳 말고는 아무것도 바뀌지 않았다는 뜻이다.
5. 결과를 다시 읽어 바뀐 자리를 눈으로 확인한다: `python3 HWP read 완성.hwp` (표는 `cells`)
6. 결과 파일을 사용자에게 준다.

동작 방식(알아 두면 좋은 것):
- 바뀐 글자는 그 자리에 있던 글자 모양(굵기·크기·색)을 그대로 이어받는다.
- 여러 글자 모양에 걸친 문자열도 찾는다. 단, 표·탭·필드 경계를 넘는 문자열은 찾지 않는다(그 구조를 깨지 않기 위해).
- 바꿀 글에 줄바꿈(`\n`)을 넣으면 같은 문단 안의 줄 나눔이 된다. 탭은 공백으로 바뀐다.
- 셀 내용을 여러 줄로 주면 셀의 문단 수만큼 나눠 넣고, 남는 줄은 마지막 문단에 줄 나눔으로 들어간다.
- 고친 문단의 줄 배치는 한글이 파일을 열 때 다시 계산한다.

### 3. 새 문서 만들기 — "보고서를 한글 파일로 만들어줘"

내용을 마크다운(또는 더 세밀하게는 JSON)으로 쓰고 변환한다.

```bash
python3 HWP create 보고서.hwpx --from 내용.md --title "2026년 업무 보고"
python3 HWP create 보고서.hwp  --from 내용.md            # 사용자가 .hwp를 원할 때
python3 HWP create 보고서.hwpx --from 내용.json          # 글자 크기·색·병합 셀·여백 등
# 옵션: --font "맑은 고딕"  --size 11  --landscape
```

- **형식 선택**: 기본은 `.hwpx`(최근 한글 버전이 기본으로 쓰는 국가 표준 형식 OWPML). 사용자가 ".hwp로", "hwp 파일" 이라고 하거나 제출처가 .hwp를 요구하면 `.hwp`로 만든다.
- 지원하는 마크다운: `#`~`######` 제목, 한 줄 = 한 문단, `**굵게**` `*기울임*` `~~취소선~~` `<u>밑줄</u>`, `-`/`*` 글머리표(들여쓰면 하위), `1.` 번호, `>` 인용, GFM 표(첫 줄은 굵게+음영 머리글), `<center>…</center>` `<right>…</right>`, `<!-- pagebreak -->` 쪽 나눔.
- JSON 형식과 전체 문법은 [references/syntax.md](references/syntax.md)를 본다(글자별 크기·색·글꼴, 병합 셀, 열 너비, 용지 방향·여백).
- 제목을 가운데 두려면 `# <center>제목</center>`.
- 출력 파일이 이미 있으면 도구가 멈춘다. 고쳐서 다시 만들 때는 `--force`.
- `read` 결과에는 제목 크기·굵기가 드러나지 않는다(글자만 나온다). 서식은 도구가 입력대로 넣는다.
- 도구가 만든 직후 파일을 다시 열어 `내용 대조: 입력한 문단 N개가 모두 그대로 들어 있음`을 확인한다. 이 줄이 없거나 오류면 사용자에게 주지 않는다.

### 4. 기존 문서를 크게 고치기 / 형식 바꾸기 (hwp ↔ hwpx)

이 도구는 기존 문서의 글자를 바꾸고 셀을 채운다. 문단을 새로 끼워 넣거나 표 구조를 바꾸지는 않는다. 그런 요청이면:

1. `read`로 내용을 마크다운으로 받고 → 2. 마크다운을 고치고 → 3. `create`로 새 파일을 만든다.

이렇게 하면 **원본의 세부 서식(글꼴, 표 테두리, 쪽 설정 등)은 기본값으로 바뀐다.** 진행 전에 사용자에게 이 차이를 한 줄로 알린다. 형식 변환(hwp → hwpx 등)도 같은 방법이며 같은 한계가 있다.

## 하지 말 것

- `.hwp`/`.hwpx`를 `cat`, `open().read().decode()`, `cp949`로 열지 않는다. 깨진 글자를 보고 "인코딩 문제"라고 추측하지 않는다.
- 바이트·XML을 직접 조립해서 한글 파일을 만들지 않는다.
- LibreOffice로 변환하지 않는다(HWP 5.0을 제대로 읽지 못한다).
- 원본 파일을 덮어쓰지 않는다(도구도 거부한다). 결과는 항상 다른 이름으로.
- 도구 출력에 없는 일을 했다고 말하지 않는다. 예: "한글에서 열어 확인했다" — 이 환경에는 한글 프로그램이 없다. 도구가 하는 것은 구조 점검과 다시 읽기 대조다.

## 열 수 없는 문서

도구가 오류로 알려 준다. 사용자에게 그대로 전하고 해결 방법을 안내한다.

| 경우 | 안내 |
|---|---|
| 암호가 걸린 문서 | 한글에서 암호를 해제해 저장한 뒤 다시 |
| 배포용 문서 | 본문이 암호화되어 있다. 도구는 한글이 저장해 둔 미리보기 텍스트(앞부분)만 읽는다. 전체가 필요하면 원본(배포용 아닌) 파일 |
| HWP 3.x(한글 97 이전), .hml | 한글에서 열어 .hwpx로 다시 저장 |

## 결과 보고

사용자에게 결과를 줄 때 다음을 짧게 말한다:
- 무엇을 했는지(채운 칸 수, 바꾼 곳 수, 만든 문단·표 수)
- 찾지 못했거나 하지 못한 것이 있으면 무엇인지
- 그림 넣기처럼 이 도구가 하지 못하는 부분이 요청에 있었다면 그 사실
