# hangul-hwp — Claude가 한글 문서를 깨지지 않게 읽고 쓰게 하는 스킬

Claude(claude.ai, Claude Code, Cowork)에서 `.hwp` / `.hwpx` 파일을 다루면 글자가 깨지거나, 만든 파일이 한글에서 열리지 않는 문제를 해결합니다. 파이썬 표준 라이브러리만 쓰는 도구(`scripts/hwp.py`)와, Claude가 언제 어떻게 그 도구를 써야 하는지 적은 `SKILL.md`로 되어 있습니다.

| 할 수 있는 일 | .hwp | .hwpx |
|---|:-:|:-:|
| 읽기 (마크다운/텍스트/JSON, 표·병합 셀·머리말·각주 포함) | ✅ | ✅ |
| 글자 바꾸기 (서식·나머지 내용 그대로) | ✅ | ✅ |
| 표 셀 채우기 | ✅ | ✅ |
| 새 문서 만들기 (제목, 굵게/기울임/밑줄/취소선, 색·크기·글꼴, 목록, 표, 병합 셀, 정렬, 쪽 나눔, 가로 용지, 여백) | ✅ | ✅ |

## 설치

**claude.ai / Claude 데스크톱 앱**: 릴리즈의 `hangul-hwp.skill`을 받아 설정 → 기능(Capabilities) → 스킬에서 업로드합니다. (코드 실행 기능이 켜져 있어야 합니다.)

**Claude Code**: 이 폴더를 `~/.claude/skills/hangul-hwp/`(모든 프로젝트) 또는 프로젝트의 `.claude/skills/hangul-hwp/`에 복사합니다.

설치 뒤에는 "이 한글 파일 요약해줘", "이 양식에 내 정보 채워서 hwp로 줘", "보고서를 한글 파일로 만들어줘"처럼 평소대로 말하면 됩니다.

## 직접 쓰기 (명령줄)

```bash
python3 scripts/hwp.py read 문서.hwp
python3 scripts/hwp.py cells 양식.hwp
python3 scripts/hwp.py set-cell 양식.hwp -o 완성.hwp --table 0 --row 0 --col 1 --text "홍길동"   # 번호는 0부터
python3 scripts/hwp.py replace 양식.hwpx -o 완성.hwpx --pair "{{이름}}" "홍길동"
python3 scripts/hwp.py create 보고서.hwpx --from 내용.md
```

입력 문법은 [references/syntax.md](references/syntax.md).

## 어떻게 검증했나

이 개발 환경에는 한글 프로그램이 없습니다. 그래서 "한글에서 열린다"는 것을 직접 확인하지는 못했고, 대신 다음으로 검증했습니다.

- **읽기**: 한글이 실제로 저장한 공개 예제 93개(.hwp 44, .hwpx 49; Apache-2.0인 neolord0/hwplib·hwpxlib 저장소)를 모두 읽고, 각 파일 안에 한글이 직접 써 둔 미리보기 텍스트와 비교했습니다. 미리보기가 있는 파일은 모두 일치(그림 자리 표시 `[그림]` 하나 차이인 파일 1개 제외).
- **고치기**: 같은 예제 전부에 글자 바꾸기를 하고, 바뀐 문단이 한글 자신이 만든 문단과 같은 구조 규칙(글자 수, 글자 모양 위치, 8칸 제어문자, 문단 끝)을 지키는지, 고치지 않은 부분이 바이트 단위로 같은지 확인했습니다.
- **컨테이너**: 모든 .hwp 출력을 독립 구현인 `olefile`의 가장 엄격한 검사로 열었습니다.
- **구조**: .hwpx 출력을 OWPML 스키마로 검사해, 한글이 만든 파일에서도 나오는 오류 외에 새 오류가 없음을 확인했습니다. `python-hwpx`의 검사기도 통과합니다.
- **교차 확인**: 만든 .hwp/.hwpx를 독립 라이브러리 `python-hwpx`(한컴 호환을 목표로 HWP·HWPX를 모두 다루는 별도 구현)로 열어 경고 없이 같은 내용이 읽히고, 굵게·색·크기·취소선·아래첨자·글꼴·정렬·여백·가로 용지·음영이 의도대로 해석됨을 확인했습니다.

자동 테스트: `python3 -m unittest discover -s tests -v` (예제 폴더를 `HWP_SAMPLES`로 주면 93개 예제 검사까지).

## 한계

- 그림·도형·차트·수식은 읽을 때 `[그림]`, `[수식: …]`으로만 표시하고, 새로 넣지는 못합니다.
- 개요/문단 번호(1., 가., ①)는 한글이 화면에 그릴 때 붙이는 것이라 읽기 결과에 나오지 않습니다.
- 기존 문서에 문단을 끼워 넣거나 표 구조를 바꾸는 편집은 하지 않습니다(읽기 → 마크다운 수정 → 새로 만들기는 가능하지만 원본 서식은 기본값이 됩니다).
- 암호 문서는 열지 않습니다. 배포용 문서는 미리보기 텍스트만 읽습니다. HWP 3.x는 지원하지 않습니다.

## 보안

- 문서 내용은 어디로도 보내지 않습니다. 네트워크를 쓰는 코드가 없습니다.
- 원본은 덮어쓰지 않습니다. 결과는 임시 파일에 다 쓴 뒤 한 번에 옮겨 반쯤 쓰인 파일이 남지 않습니다.
- 악성 문서 대비: 압축 해제 크기 상한(스트림·항목당 256MB, 전체 512MB), XML의 DTD/엔티티 선언 거부, 순환하는 섹터 체인 탐지.
- 새로 만드는 문서에는 작성자·시각·기기 정보를 넣지 않습니다.
